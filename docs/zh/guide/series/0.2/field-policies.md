# 0.2 候选：全系统字段权限

**0.2 尚未正式发布。** 本页描述当前开发候选的契约，最终产物与生产升级支持以[更新说明](../../reference/versions.md)及正式不可变清单为准。配套来源见[系列首页](index.md)，停写与恢复见[升级指南](upgrade.md)。App/Desktop 未纳入正式发布范围。

## 范围与权限关系 {#策略怎样影响用户操作}

当前通用目录包含23个对象、250个字段、128个登记动作，覆盖以下入口。不是所有数据库列都可授权；密码、密钥、租户锚点和平台固定边界不能被角色规则放开。

| 范围           | 对象                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| 普通与关系对象 | 用户、字典类型、字典项、数据范围演示、角色、部门、菜单                         |
| 配置与调度     | 系统配置、系统设置、任务定义                                                   |
| 传输与文件     | 文件、导入批次、导出任务、传输审计                                             |
| AI与日志交付   | 助手、会话、消息、AI操作日志、路由日志与反馈、系统操作日志、登录日志、任务日志 |

菜单与功能权限决定能否调用动作，数据范围决定可访问哪些记录，字段规则决定在该用途下能读写哪些字段。三者同时成立才允许操作。角色的字段允许不能借用另一个角色的更大记录范围；同一记录上的显式拒绝优先。`R_SUPER` 也不绕过业务字段规则。最小身份、导航、公开账号能力及平台控制面使用各自固定协议，不能作为任意业务字段的副本或授权通道。

多租户中的字段规则属于具体租户和角色。租户开户、启用与字段激活是不同操作；平台主体权限不能替代租户字段授权。通用部署中新租户建立空策略状态，不自动继承默认租户规则；引导后由有专用权限的租户管理员配置并显式激活。缺少本租户策略状态时也拒绝旧兼容回退。未迁入通用目录的旧部署有明确兼容边界，不能据此推断启用后的默认权限。

## 在角色管理中配置

入口位于“系统管理 → 角色管理”的行操作，**字段权限紧邻菜单权限右侧**。管理者须有启用的 `R_SUPER` 和显式 `system:role:field-policy-view`；编辑与标记待激活需要 `system:role:field-policy-edit`，激活与冻结需要 `system:role:field-policy-activate`。通配按钮权限不能代替这些专用码。升级前须为每个已初始化或启用租户显式配置，禁用租户也不能遗漏。

角色业务字段未就绪或被冻结时，清空业务筛选后，具备专用权限的管理员可以看到仅含角色ID的修复行，仍从行内字段权限进入；角色名称等受保护字段不猜测补齐，其他业务写入口关闭。策略生效后刷新恢复原业务列表。

抽屉分为“读取与查询”“新增与修改”“导入与导出”。每个对象只显示服务端实际支持的用途。

| 用途 | 含义                                                         |
| ---- | ------------------------------------------------------------ |
| 读取 | 查看当前允许的原文或脱敏值，包括登记的列表、详情与派生展示   |
| 查询 | 筛选、匹配、排序、关联或聚合等实际登记的查询用途             |
| 新增 | 普通新增时可提交的字段                                       |
| 修改 | 普通修改时可提交的字段，允许与读取分开配置                   |
| 导入 | 分别检查导入新增、修改和匹配，也检查服务端填充的默认值与关系 |
| 导出 | 与读取、记录范围及导出功能权限求交集                         |

六类用途不自动覆盖密码重置、关系授权、配置发布或任务运行等专用动作。自定义功能按钮必须由后端登记动作与字段用途映射，拥有按钮不能取得额外字段许可。导入按钮也不能复用普通新增/修改权限绕过导入用途。

**启用后未配置表示未授予。** 新角色、新对象或新增用途不默认拥有全部字段。“默认推荐配置”仅补当前对象尚未配置的安全读取/查询，保留显式拒绝与已有写入设置；它不会自动执行。“全部允许”“全部拒绝”位于其右侧，作用于当前对象、当前页签的完整目录，与搜索过滤无关。结构字段、密码等跳过批量授予，敏感读取遵守脱敏上限。

## 候选、激活与冻结

本人账户有代码登记的最小自助基线。移除某个允许规则不会取消该基线；限制本人手机号或邮箱时，须配置对应 `own-account` 用途的显式拒绝，该拒绝也约束个人资料与邮箱查询。自助用途不能取得管理用途的其他字段。

保存候选不改变当前活动策略。预览只显示抽象规则差异，不返回业务原值；填写理由后保存，再封存本租户完整的角色/对象候选清单。不能用当前抽屉或搜索结果冒充完整清单。

| 状态或操作  | 行为                                                                   |
| ----------- | ---------------------------------------------------------------------- |
| `preparing` | 通用状态已建立，业务字段入口失败关闭，保留获授权的控制面修复           |
| ready       | 为完整候选建立有限期就绪水位，不是活动切换；最长15分钟                 |
| activate    | 在当前资格、版本与epoch下原子切换本租户完整清单                        |
| `enforcing` | 业务统一使用封存活动清单；之后保存新候选仍不立即生效                   |
| `frozen`    | 冻结对象及其来源依赖闭包，保留历史和修复入口；恢复需重新核验并显式激活 |

部署方还须提供绑定精确Backend构建、当前目录和全部入口验收证据的服务端资格。缺失或过期时可以修复候选，不能ready/activate。两步分别确认完整候选；候选、授权、目录或epoch变化使旧就绪水位失效。首次激活后不能退回旧兼容状态。未知提交结果保留requestId，只核对回执，不自动重提。切换登录身份清除草稿，旧对话框和迟到响应不能操作新身份的策略。

API、封闭请求与资格格式见固定源码的[管理契约](https://github.com/aihohu/hohu-admin/blob/1b6abcd85ae800047b72d97d15ff07b52a8aafd0/docs/FIELD-POLICY-MANAGEMENT.md)及[存储契约](https://github.com/aihohu/hohu-admin/blob/1b6abcd85ae800047b72d97d15ff07b52a8aafd0/docs/FIELD-POLICY-STORAGE.md)。新管理协议的ID、版本与epoch均为十进制字符串；浏览器不能提交租户、actor或资格声明。

## 列表、关系、导入与下载 {#编辑、查询和下载}

隐藏字段从DTO中省略，`null` 表示实际空值。Web按实际投影生成业务列；没有该字段许可时不显示整列“无权限”占位，按记录范围存在差异时也不补原值。导出隐藏列不写入文件。只写字段不回填原值；未操作的替换输入不提交，显式编辑为空值时按该字段的空字符串或 null 契约处理。

新Web只提交实际变更字段。旧整对象表单每个携带字段都须可写，包括值未变化的字段；旧页面被拒绝后应换用配套Web核对修改，不能循环重发或靠版本Header豁免。关系集合须完整可见且允许替换，不能把部分结果写回整个集合。派生的负责人、部门或角色名称还要满足其来源字段权限。查询检查完整作用域，不能仅验证本页数据；筛选、排序与total也受用途约束。

模板、导入预览、默认字段、匹配与最终写入共享登记契约。导出按当前读取与导出交集生成。错误文件、导出文件及旧链接的下载重新检查当前授权、来源和文件内容；收到 `FIELD_TRANSFER_REGENERATE_REQUIRED` 时，在当前授权下重新生成。登录后的受控下载不能被裸文件地址代替。

## AI、审计与后台 {#ai-与历史记录}

模型上下文、工具预览、确认、执行、历史、缓存与最终结果交付都按登记用途和来源重验。确认前权限或epoch变化时需要重新预览；已经成功的业务不能因结果不可见而改判失败，结果未知也不能自动重做。模型叙述不替代工具卡与数据库事实。

会话、文件或历史正文缺少可信来源时保持隐藏或拒绝交付，保留审计事实，不补认领为当前用户数据。日志可读不意味着请求参数、错误正文或模型输出全量可读。配置值与任务参数按动态值/任务规格分类，不能通过字段允许开放任意秘密或代码。后台任务、恢复和过期扫描也纳入同一停写与交付约束。
