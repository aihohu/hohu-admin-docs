# 0.2 候选：用户字段策略

本页说明 **尚未正式发布的 0.2 开发候选**。当前稳定版本及正式产物仍以[更新说明](../../reference/versions.md)为准；0.1 手册保留在原路径；请从[系列首页](index.md)查看当前文档范围。本页不是生产升级许可，也不启动 0.1 弃用或维护结束倒计时。Backend 与 Web 必须配套验收；App/Desktop 尚未正式发布，CLI 的版本独立管理。

## 策略怎样影响用户操作

字段权限同时受租户、功能权限、记录范围、字段及用途约束。一个角色对财务部门邮箱的授权，不能借另一个角色的全公司记录范围扩展到其他部门。同一记录上的显式拒绝优先；超级管理员管理策略的权限也不意味着能绕过业务字段规则。新角色或新字段不会自动取得字段授权。

在角色管理中打开“用户字段策略”，选择字段、操作及用途，预览无业务原值的影响样本，填写理由后发布。发布候选与首次激活是不同操作：

| 状态        | 行为                                                                           |
| ----------- | ------------------------------------------------------------------------------ |
| `legacy`    | 沿用兼容授权路径，尚未启用字段策略                                             |
| `ready`     | 候选已准备，仍未生效                                                           |
| `enforcing` | 当前活动策略统一约束已接入的用户入口；发布新修订立即生效                       |
| `frozen`    | 用户业务读写关闭；保留最小身份和获授权的策略修复入口，发布修复后须显式重新激活 |

策略管理需要 `R_SUPER` 和相应的 `system:user:field-policy-view`、`system:user:field-policy-edit`、`system:user:field-policy-activate` 权限。升级后的既有角色需显式授权。部署者还必须提供绑定当前构建的资格文件，不能仅靠角色权限启用功能。版本冲突时重新加载、核对再提交；不要自动重试发布或激活。

激活不可逆：已激活租户不能退回 `legacy` 或 `ready`。具体接口及部署资格格式见固定候选源码中的[后端字段契约](https://github.com/aihohu/hohu-admin/blob/fb0edbd7879a7ff14df7f010eea7dc4e7faddba5/docs/USER-FIELD-PROJECTION.md)。正式发布后应使用产品清单绑定的文档快照。

## 编辑、查询和下载

隐藏字段不出现在响应中；`null` 表示真实空值，不表示隐藏。手机号、邮箱仍受各入口既有脱敏上限约束。只写字段不会回填原值，编辑时填写新的替换值；空白替换默认不修改，清空使用明确的清空操作。

本人账户使用固定的自助权限基线。仅移除某个允许规则，不会取消这份基线；需要限制本人手机号或邮箱时，应配置对应 `own-account` 用途的显式拒绝。该拒绝也约束个人资料和邮箱查询入口。

新 Web 只发送实际修改字段的 PATCH。省略表示保持原值，可空字段的显式 `null` 表示清空。不能提交掩码占位符。角色或部门关系需要完整可见且允许替换，不能把部分展示结果写回为整个集合。查询、聚合及固定排序同样需要权限；缺少排序字段读权时，列表请求也可能被拒绝。

旧 PUT 仍保留，但每个携带字段都必须可写，包括值未变化的字段。已打开的 0.1.6 页面可能提交整个表单而被拒绝，此时刷新到配套新 Web 后重新核对修改，不要循环重发。客户端版本标记不能豁免服务端授权。

导入在创建持久预览和写入前检查完整字段要求；工号匹配、默认字段和关系赋值也在检查范围内。导出取读取与导出权限的交集。文件下载重新验证当前权限、来源和文件内容；收到 `FIELD_TRANSFER_REGENERATE_REQUIRED` 时，在当前授权下重新生成文件。错误附件通过登录后的下载入口获取，不能直接打开裸地址绕过认证。

## AI 与历史记录

确认前发生目录、权限或策略变化时，旧确认可能失效，需要重新预览。已经成功的业务不会因为结果不可见而改为失败；执行结果未知也不能自动重做。历史正文或文件缺少可证明的字段来源时，激活后隐藏或拒绝交付，审计事实仍然保留。模型叙述不替代实际工具结果和数据库状态。

升级、停写和恢复要求见[0.2 升级与恢复](upgrade.md)。
