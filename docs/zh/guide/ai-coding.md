# 使用 AI 开发业务应用

本页面向使用 Claude Code、Cursor、Codex、OpenCode、TRAE 等编程助手开发 HoHu 源码的开发者。以下设备借用流程是开发示例，不是产品内置模块。

## 准备工作 {#prerequisites}

1. 按 [安装 Skills](./cli/skills)安装 `hohu-project` 和 `hohu-business-module`，在当前工作区确认助手已识别。
2. 安装 [HoHu CLI](./cli/index#installation)，准备 [开发环境](./quick-start)及独立开发数据库、Redis。
3. 新建项目时，从目标父工作区启动助手；已有项目则打开 Backend/Web 的共同项目根目录。提供明确路径，避免助手修改其他项目。

| 阶段       | 使用的 Skill           | 应交付什么                                             |
| ---------- | ---------------------- | ------------------------------------------------------ |
| 创建并运行 | `hohu-project`         | 实际组件目录、初始化结果、服务地址和访问验证           |
| 开发模块   | `hohu-business-module` | 迁移、Service/API、权限、页面、应用 AI 工具和测试      |
| 调整需求   | `hohu-business-module` | 与当前实现匹配的变更、兼容处理和回归结果               |
| 验证交付   | 对照项目检查和业务场景 | 可用页面、普通用户授权验证、真实 AI 结果或明确验证缺口 |

## 1. 创建并运行项目 {#create-project}

在父工作区提出：

> 使用 hohu-project 创建 equipment 项目，只需要 Backend 和 Web。检查本机依赖和数据库配置，初始化并启动，完成后给出组件路径、访问地址与验证结果。

助手应先检查实际 CLI 版本和帮助。支持显式组件选择的版本使用 [非交互创建](./cli/create#examples)。已有同名目录不能覆盖；克隆失败时先检查保留内容再恢复。

初始化会安装依赖、执行迁移和种子同步。准备项目自身的环境配置，保留已有凭据和设置。结果应区分创建目录、完成初始化、服务可访问及登录已验证；仅有 CLI 的最终提示不能证明全部完成。

## 2. 开发设备借用模块 {#build-module}

在已运行的项目中提出：

> 使用 hohu-business-module 开发设备借用模块。设备包含名称、编号和可借用状态；支持借用、归还及查看借用记录。同一设备不能被同时重复借用。普通用户只能查看和归还自己的记录。提供 Web 页面及应用 AI 查询、确认后借用和归还。业务内容只需中文。

说明业务对象、操作、约束和可见范围，比只说“做个设备管理”更容易得到可核验的结果。未确定的归还规则、管理权限或已有数据兼容方式，应在实现前明确。

助手先检查项目规范和兼容性，再完成迁移、Service/API、功能权限、页面和应用 AI 工具。新模块遵循目标项目标准目录，扩展既有模块则保留其布局。业务模块默认接入应用内 AI；国际化按你的明确要求，未说明时沿用业务模块惯例，不修改 HoHu 自带国际化。

权限和并发约束需要在业务 Service 中落实，按钮隐藏或提示词不能代替后端校验。实现参考见 [新增业务模块](./development/module)、[功能权限](./auth)、[数据范围](./data-permission)及 [业务工具接入](./development/ai-tools)。

## 3. 调整已有需求 {#iterate}

基于实际交付继续提出小范围变更，例如：

> 在现有设备借用模块增加借用备注，最长 200 字；页面、接口和 AI 工具同步支持。已有记录允许备注为空，保留原有权限和重复借用约束，补充迁移与回归验证。

先检查变更涉及的数据兼容、接口、页面和 AI 工具，再验证新需求及原有流程。不要因一次调整而重建整个项目或覆盖已有数据。

## 4. 验证交付 {#verification}

| 检查         | 完成标志                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 源码与迁移   | 迁移和代码差异已审阅，静态检查、测试及覆盖率门禁通过                   |
| 页面流程     | 普通用户可借用和归还，刷新后结果仍存在，记录列表与分页正确             |
| 业务约束     | 同一设备不能重复借用；页面和直接接口都遵守权限                         |
| 数据范围     | 其他用户及其他租户数据不会越权出现                                     |
| 应用 AI 查询 | 查询页面创建的数据，出现实际工具记录且对象一致                         |
| 应用 AI 写入 | 先展示确认，取消不写入，批准后业务页面更新；按场景验证重放、过期和撤权 |

应用模型与编程助手模型独立。未配置应用模型时可以完成源码和确定性测试，但真实 AI 使用应标记为未验证；配置见 [首次配置 AI](./operations/ai#first-setup)。工具可用不等于每次自然语言请求都能准确完成，需要检查实际工具结果。

交付应包含变更摘要、已运行检查、访问地址、运行/停止方式与剩余配置。正式手册同步当前行为；草案、计划和一次性报告保存在本地。提交、推送及部署按项目流程分别执行。
