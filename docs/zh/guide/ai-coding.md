# 使用 AI 与 HoHu Skills 开发业务应用

本页面向使用 Claude Code、Cursor、Codex、OpenCode、TRAE 等编程助手开发 HoHu 源码的开发者。先按[安装 Skills](./cli/skills)安装所需工作流，并准备[开发环境](./quick-start)。

## 创建并运行项目

在准备创建项目的父工作区启动 Agent，确认它能发现 `hohu-project`。项目创建需要 HoHu CLI 和终端执行能力。提出：

> 使用 hohu-project 创建 equipment 项目，只需要 Backend 和 Web。检查本机依赖和数据库配置，初始化并启动，完成后告诉我访问地址与验证结果。

助手会检查当前 CLI 的帮助信息；支持显式组件的版本可使用[非交互创建](./cli/index#非交互创建)。已有同名目录不能覆盖；网络克隆失败后应检查保留的目录再处理。

初始化会涉及依赖、数据库迁移和种子数据。提供独立的开发数据库与 Redis，并按项目要求准备环境配置。成功结果应包括实际组件目录、初始化结果、服务地址和页面访问检查；仅创建目录不表示项目已经可用。

## 开发业务模块

在已有项目中使用 `hohu-business-module`，说明业务操作和数据可见范围，例如：

> 新增设备借用模块，支持借用、归还和查看记录。普通用户只能查看和归还自己的借用记录，不能重复借用同一设备。业务内容只需中文。

助手先检查项目规范及兼容性，再完成迁移、Service/API、功能权限、页面和应用 AI 工具。新模块使用目标项目的标准目录，扩展既有模块时遵循现有布局。

业务模块默认接入应用内 AI 查询及所需写入工具，复用平台确认机制。业务国际化遵从你的明确要求；未说明时沿用目标项目的业务模块惯例，不改变 HoHu 自带国际化。功能权限、租户隔离和数据范围根据业务需求接入现有权限体系，无需额外选择通用能力开关。

需要手动理解实现时，阅读[新增业务模块](./development/module)、[功能权限](./auth)、[数据范围](./data-permission)和[业务工具接入](./development/ai-tools)。

## 验证结果

1. 检查迁移和代码差异，运行目标仓库的静态检查、测试及覆盖率门禁。
2. 使用普通用户操作页面并刷新，确认记录、分页和按钮权限；直接请求无权接口也应被拒绝。
3. 按业务可见范围验证其他用户与其他租户的数据不可越权访问。
4. 使用真实模型查询页面创建的记录，检查实际工具调用。写入先出现确认卡片，批准后才落库；取消、重放和撤权场景按业务要求验收。

应用内模型配置与编程助手的模型配置独立。没有可用的应用模型时，可以完成源码和确定性测试，但真实 AI 场景应记为未验证；模型准备见[配置与运维](./operations/ai)。

将已交付功能和操作方法更新到对应手册。草案、计划和一次性验收记录保存在本地；提交、推送和部署按项目流程分别执行。
