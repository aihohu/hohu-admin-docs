# 错误处理

业务 API 使用 `{code, msg, data}`，错误可提供稳定的 `errorCode`，前端用它映射语言资源。不要按 msg 的中文或英文字符串判断逻辑。

```json
{ "code": 409, "msg": "设置已变更，请重新加载", "data": null, "errorCode": "SETTINGS_CONFLICT" }
```

示例用于说明格式，不要求实际 msg 与示例完全一致。客户端同时处理 HTTP 状态、响应结构和网络失败；不是所有代理拒绝都一定有业务 JSON 正文。

## 新增错误

使用 `app/core/exceptions.py` 中的领域异常，选择稳定、能表达业务原因的错误码，避免业务层散落 HTTPException。同步前端语言映射和正反路径回归，日志中的敏感数据必须脱敏。

并发冲突应提示重新读取，权限拒绝不能重试成成功，429 按 Retry-After 等待；503 先检查部署开关与依赖，不能通过无限重试掩盖故障。

本站仅维护[常见错误码](./error-code-list)的排查指引，完整情况以目标版本代码与实际接口为准。新增模块不得把未覆盖的人工表格当成错误码注册表。
