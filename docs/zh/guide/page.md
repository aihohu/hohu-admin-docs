# 分页查询

工具位于 `app/utils/pagination.py`。业务查询 Schema 使用 `current`（从 1 开始）、`size`，并校验正数和最大页大小。

| 入口              | 用途                       | 记录类型             |
| ----------------- | -------------------------- | -------------------- |
| `paginate`        | 单模型分页，可预加载关系   | ORM 实体列表         |
| `paginate_custom` | JOIN、多列或聚合查询       | SQLAlchemy Row 列表  |
| `build_filters`   | 从受控字段映射生成业务条件 | 条件列表，不自动授权 |

传给分页工具前，先添加可信租户条件，再添加[数据范围](./data-permission)和业务筛选。工具不自动推断 tenant。列表与 count 必须使用相同授权条件。

自定义 JOIN 或聚合显式提供 `count_query`，明确统计实体还是分组，处理关联重复行。自动计数推断失败可能回退 0，不代表业务总数正确。

使用稳定排序，相同时间的记录增加唯一 ID 次排序。将 ORM/Row 映射到响应 Schema，Snowflake ID 输出字符串。只预加载实际需要的关系，避免 N+1，并依据查询计划评估索引。

大批量导出使用独立受限流程，不通过超大 size 绕过资源限制。动态条件使用 SQLAlchemy 表达式与参数绑定，不拼接用户输入 SQL。
