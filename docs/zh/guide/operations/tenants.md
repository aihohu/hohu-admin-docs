# 多租户管理

默认 `TENANT_MODE=single` 使用默认租户。部署多业务租户时，配置 `TENANT_MODE=hosted` 与 `TENANT_HOSTED_LOGIN_ENABLED=true`；生产 hosted 还需准确的完整 `RELEASE_BUILD_SHA`。环境值必须实际传入后端进程，修改后重启并核查，不假定 `.env` 中任意新键都会自动透传。

## 开通租户

1. 默认租户内拥有启用系统超级管理员角色的用户登录，进入租户管理。
2. 创建租户并设置明确的租户代码。账号名不授予此权限。
3. 初始化租户管理员、基础角色、菜单、设置及必要 AI 绑定，再启用租户。未初始化不能启用。
4. 通过租户代码或配置的 Host 后缀登录业务租户，使用普通账号验证隔离。

API 创建和初始化各自使用稳定的 `Idempotency-Key`；失败后重试原步骤，不换新键重复创建。初始化不从默认租户的可编辑菜单或设置复制授权，新租户按固定默认值启用文件解析；存量租户的显式禁用不被覆盖。

## 停用与边界

停用保留数据，重新启用不重置密码与角色；旧 Token 不会随重新启用而恢复有效。关闭全局 hosted 登录开关会拒绝业务租户运行，默认租户仍可维护。

系统管理操作需要原因、工单和关联信息，并留存审计。Provider/模型目录、Agent 与租户模型授权统一使用默认租户系统超级管理员的正常登录会话。

租户管理员只管理本租户。当前不开放 hosted Marketplace/Lowcode、跨租户成员关系、在线租户切换、BYOK 或 PostgreSQL RLS 隔离。主应用也未注册应用市场路由，不应按历史插件安装设计启用。

维护者需要遵守的约束见后端仓库的 `docs/ARCHITECTURE-GUIDELINES.md` 和 `docs/SECURITY.md`，仓库位置见[源码入口](../src)。
