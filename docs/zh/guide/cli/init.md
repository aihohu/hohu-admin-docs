# hohu init

安装项目标记中声明的组件依赖，并执行存在的组件初始化脚本。标准 Backend 会准备环境文件、迁移数据库并同步基础数据。

## 前提条件

完成 [`hohu create`](./create)，所选目录均存在。在包含 `.hohu/project.json` 的项目根目录或子目录运行。按[开发环境教程](../quick-start)准备运行环境、PostgreSQL 和 Redis，核对目标数据库及连接配置。

首次环境文件与连接配置的处理步骤见教程。初始化可能连接数据库并修改其结构和基础数据。

## 用法

```bash
hohu init
```

没有组件筛选参数。按项目标记中的顺序执行，缺失的组件目录会跳过。

## 执行过程与结果

| 组件    | 首选依赖安装   | 初始化                       |
| ------- | -------------- | ---------------------------- |
| Backend | `uv sync`      | 执行存在的 `scripts/init.py` |
| Web     | `pnpm install` | 无额外 CLI 初始化脚本        |
| App     | `pnpm install` | 无额外 CLI 初始化脚本        |

安装失败会尝试备用命令：Backend 为 `pip install -r requirements.txt`，Web/App 为 `npm install`。备用命令能否成功取决于实际项目文件和工具环境。

标准后端初始化会：

1. 从 `.env.example` 创建缺失的 `.env`，生成应用密钥。
2. 在未提供 `HOHU_ADMIN_PASSWORD` 时生成首次管理员密码。
3. 执行 `alembic upgrade head`，然后运行基础数据初始化。

已有 `.env` 会保留；基础数据同步保留已有管理员密码和用户自定义内容。凭据位于后端 `.env`，详见[首次登录](../quick-start)。初始化不启动开发服务或准备 Docker 部署配置。

完成后检查各组件安装输出、后端迁移和初始化结果，再运行 [`hohu dev`](./dev)，通过登录确认服务可用。无需重复运行内部初始化脚本。

## 失败后重试

修复错误后，在同一项目重新运行 `hohu init`。

| 现象                     | 处理方式                                               |
| ------------------------ | ------------------------------------------------------ |
| 找不到项目               | 进入包含 `.hohu/project.json` 的目录                   |
| 数据库或 Redis 连接失败  | 检查服务、数据库和 `hohu-admin/.env`，修正后重试       |
| 依赖安装失败             | 阅读出错组件输出，核对运行环境、网络和锁文件           |
| 目录或初始化脚本缺失     | 检查源码完整性；目录可能被跳过，缺失脚本可能仅产生警告 |
| Windows symlink 权限错误 | 开启 Windows 开发者模式，检查目录写入权限              |

最后一行提示不能代替对每个组件的核查。迁移失败后按实际错误恢复，不要通过删除数据库来重试。
