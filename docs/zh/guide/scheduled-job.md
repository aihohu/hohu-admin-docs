# 定时任务

任务注册与调度配置分离。开发者注册可执行函数，管理员在任务页面选择已注册的任务、调度方式和参数，启用后由调度器执行并记录日志。

## 进程架构

`APP_ROLE=api` 只运行 API，`scheduler` 运行独立调度进程，`all` 用于单进程开发。生产 API 不使用 all 配合多个 worker，否则可能重复触发任务。CLI 部署将 API 与 scheduler 分开。

## 开发接入

1. 在后端任务模块使用 `app.modules.job.task_registry.register_task` 注册唯一 key，确保启动时导入该模块。
2. 明确 `TaskScope.TENANT` 或 `TaskScope.PLATFORM`；租户可选任务不包含平台任务。
3. 接收执行链提供的可信上下文，不从用户参数构造任意租户权限，不在全局单例保存执行状态。
4. 为长任务配置 `timeout_seconds`，定义重复触发的幂等与并发策略，记录成功和失败。
5. 在隔离环境验证启停、超时、撤权、重启和跨租户拒绝，再开放给管理员。

## 管理操作

管理员创建任务时选择注册 key，配置 cron 或 interval 规则，核对参数、并发策略与启用状态。执行后查看任务日志；长期 RUNNING 时先检查进程、超时和恢复逻辑，不直接重新触发可能产生重复副作用的任务。

任务代码是后端发布的一部分，页面不能通过任意函数名获得未注册代码执行权限。定时任务不等同于 AI 确认后的持久异步执行能力。
