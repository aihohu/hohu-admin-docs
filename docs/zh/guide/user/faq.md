# 常见问题

先记录当前租户、操作步骤和页面提示，再按下表定位。不同账号的菜单与数据范围可能不同。

## 账号、注册与邮件 {#account}

| 现象                       | 先做什么                                                         |
| -------------------------- | ---------------------------------------------------------------- |
| 密码登录失败               | 核对站点、租户、用户名和密码；请管理员检查账号及租户是否启用     |
| 没有注册或忘记密码入口     | 管理员检查当前租户的相应开关及部署邮件服务是否可用               |
| 注册后只有个人账户         | 默认不授予业务权限，请管理员按需分配角色与部门                   |
| 收不到验证码               | 核对邮箱和租户，检查垃圾邮件；找回密码还要求用户名匹配已验证邮箱 |
| 找回提示已发送，却没有邮件 | 这是统一提示，不确认账号匹配；检查恢复邮箱是否验证、账号是否启用 |
| 验证码无效                 | 使用当前租户、当前用途的最新验证码；过期或重发后不要使用旧码     |
| 邮箱显示未验证             | 在个人账户的恢复邮箱页签完成验证，管理员填写邮箱不等于本人验证   |

操作步骤见[账号与登录](./account)，管理员配置见[邮件服务](./settings#mail)及[账号自助服务](./settings#account-self-service)。

## 菜单与数据权限 {#permissions}

1. 检查用户和角色是否启用，用户是否实际分配了该角色。
2. 缺少菜单或按钮时，检查角色的菜单授权和具体操作权限。
3. 看不到记录时，检查所属部门、角色数据范围及是否进入正确租户。
4. 可见记录超出预期时，检查所有启用角色；多个角色的数据范围取并集。
5. 刷新页面或重新登录，用受影响的普通账号复核。

需要授权的变更交给管理员处理，参阅[角色与权限](./roles)。不要共享同事账号验证权限。

## 设置、文件与导入 {#operations}

| 现象                     | 处理方式                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 系统设置无法保存         | 检查编辑权限和字段提示；版本冲突时重新加载再合并修改                                   |
| 看不到邮件服务或访问保护 | 这些分组需要默认租户的系统超级管理员身份                                               |
| 自定义参数不生效         | 核对参数键、启用状态及业务代码是否读取它，见[自定义参数](./parameters)                 |
| 上传失败或 413           | 检查场景格式、单文件与请求总大小，见[文件限制](./files#limits)                         |
| 用户导入被拒绝或部分失败 | 检查预检查与执行结果中的字段、部门、角色和授权范围，见[导入说明](./user-import-export) |
| AI 没有助手、模型或工具  | 管理员检查入口权限、助手绑定、模型策略和工具授权，见 [AI 配置](../operations/ai)       |

## 429 与 503 的区别 {#service-errors}

| 错误              | 含义与处理                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| 429，请求过于频繁 | 请求或验证码操作超过额度，按重试提示等待，避免连续提交；持续影响正常使用时请管理员检查策略      |
| 503，服务暂不可用 | 可能是访问保护依赖不可用、AI 被部署开关关闭或其他服务依赖异常；记录错误码与时间，交由部署者检查 |

503 不等于请求次数过多，不能通过增加限流额度解决所有 503 问题。

## 如何反馈问题 {#report}

提供产品版本、发生时间及时区、所在页面、复现步骤、预期结果、实际错误码和脱敏截图。不要提供密码、验证码、Token、完整配置文件或他人的业务数据。

先联系所在组织的管理员。确认是产品问题时，可通过导航中的“问题反馈”提交；升级后出现问题，请部署者核对[版本与兼容关系](../reference/versions)。
