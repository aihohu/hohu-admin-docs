# 用户导入与导出

在 **系统管理 → 用户管理** 使用导入、导出及导入历史入口。需要对应操作权限，导入涉及的角色与部门也必须在当前账号授权范围内。

## 准备导入文件 {#template}

1. 打开导入窗口，下载最新的 XLSX 模板。
2. 查看模板中的“说明”“部门字典”和“角色字典”，在“数据”工作表填写用户。
3. 删除示例行，保留表头。部门或角色发生变化后重新下载模板。

支持 **XLSX 和 CSV**，单次最多 2,000 行；文件大小同时受租户上传策略和解析器上限约束。推荐从下载的 XLSX 模板开始。

| 字段                       | 填写说明                                                   |
| -------------------------- | ---------------------------------------------------------- |
| `user_name`                | 必填，登录用户名；按模板和预检查提示校验                   |
| `nickname`                 | 用户昵称                                                   |
| `user_email`、`user_phone` | 邮箱、手机号，按字段格式填写；导入邮箱不会完成验证         |
| `dept_input`               | 必填，部门名称或完整路径；存在重名时使用完整路径           |
| `role_input`               | 角色标识或名称，多个角色用英文逗号分隔；只能使用可分配角色 |
| `user_gender`              | `0` 未知、`1` 男、`2` 女；默认 `0`                         |
| `status`                   | `1` 启用、`2` 停用；默认 `1`                               |
| `employee_no`              | 可选工号，默认下载模板未包含此列；按工号同步时可添加该表头 |

用户名、手机号和工号等应作为文本保存，避免表格软件改变内容。CSV 中包含逗号的角色单元格需要按 CSV 规则加引号。

新建用户使用系统配置的默认密码，导入文件不用于批量设置或覆盖已有用户密码。导入前由管理员确认默认密码可用，完成后请用户自行修改。

## 预检查与执行 {#import}

1. 填写本次导入原因，再选择文件。
2. 查看预检查结果中的新增、已存在、冲突和超出权限范围记录。预检查不会创建用户。
3. 修正不正确的部门、角色或字段后重新上传。确认重复用户和工号的处理策略。
4. 点击确认导入，等待执行结果。
5. 核对成功、跳过、更新及失败信息；按失败行提示修改数据，重新预检查后处理。也可从导入历史查询批次。

执行时会重新检查数据和授权，因此预检查通过不保证全部执行成功。文件、权限或相关数据变化后，按提示重新预检查。

## 如何处理已有用户 {#conflicts}

**按用户名匹配时**，使用冲突策略：

| 策略           | 结果                                                           |
| -------------- | -------------------------------------------------------------- |
| 跳过已存在     | 保留已有用户，默认选择                                         |
| 覆盖已存在     | 更新允许的资料及授权关系字段，不能覆盖密码、用户 ID 和创建时间 |
| 首个冲突即终止 | 执行检查发现冲突或失败记录时终止该批，不写入本批用户变更       |

**按工号匹配时**，使用同步模式：

| 模式                      | 结果                                                 |
| ------------------------- | ---------------------------------------------------- |
| 仅新增 `CREATE_ONLY`      | 默认模式，已存在工号记为失败，不更新对应用户         |
| 更新资料 `UPDATE_PROFILE` | 更新允许的资料和关系字段，保留用户名                 |
| 完整同步 `FULL_SYNC`      | 在允许范围内同步资料和关系，还可修改匹配用户的用户名 |

工号匹配优先于用户名匹配。因此选择“仅新增”并不代表所有用户名冲突都被拒绝，未按工号匹配的行仍采用冲突策略。

覆盖可能改变部门归属及角色关系，应先核对文件和授权范围。预检查阶段可取消批次；取消不应作为已执行数据的撤销方式。

## 导出用户 {#export}

1. 在用户列表设置筛选条件。
2. 打开导出窗口，填写导出原因并核对范围。
3. 确认后下载 XLSX 文件，并检查内容是否符合预期。

当前 Web 导出传递的条件为 **用户名、昵称、邮箱、手机号和状态**。性别及角色筛选尚未随导出请求传递，不要依赖它们缩小导出范围；导出也不以勾选行作为范围。服务端仍执行当前账号的数据范围限制。

数据量超过同步导出限制时，先缩小上述支持的筛选范围再试。导出包含用户信息，请按组织的数据使用要求保存和共享。

## 常见问题

**部门或角色找不到？** 核对名称、完整部门路径、启用状态和当前账号可授权范围，不要直接复制其他租户的字典。

**预检查后提示过期或授权变化？** 使用最新文件重新预检查，再确认执行。

**只导入了一部分？** 以执行结果和导入历史为准，检查失败行及已成功记录后再重试，避免盲目覆盖。
