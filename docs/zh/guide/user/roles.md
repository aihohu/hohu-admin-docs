# 角色与权限

进入 **系统管理 → 角色管理**。创建、编辑、菜单授权和 AI 助手授权分别需要对应权限，且只能操作当前账号可管理的角色。

## 创建角色与授权

1. 点击新增，填写角色名称、角色标识和说明，设置启用状态及数据范围。
2. 保存后，在该角色行点击 **菜单权限**。
3. 勾选需要的菜单及其操作按钮，确认保存。能进入页面不代表可以执行页面上的全部操作。
4. 在[用户管理](./users)中为目标用户分配角色。
5. 用目标账号检查菜单、按钮及可见记录。

角色标识用于系统识别，名称用于展示。修改已有角色前先确认哪些用户依赖该角色；停用角色后，其授权不再作为启用角色参与权限计算。

## 选择数据范围 {#data-scope}

| 范围         | 含义                                   |
| ------------ | -------------------------------------- |
| 全部         | 当前租户内、适用数据范围规则的全部数据 |
| 本部门       | 按用户所属部门确定范围                 |
| 本部门及以下 | 在所属部门基础上包含下级部门           |
| 自定义部门   | 使用为该角色选定的部门范围             |
| 仅本人       | 仅当前用户对应的数据                   |

选择自定义部门时，还需要在角色编辑页面选定具体部门。数据范围不会授予菜单或操作权限，业务模块也需要接入对应的数据范围规则。

**多个启用角色的范围取并集。** 例如，一个角色允许本部门，另一个允许指定部门，用户可以访问两者授权的数据。要收窄权限，应检查全部启用角色，不能只修改其中一个。

## AI 助手授权 {#ai-access}

在角色行使用 **AI 助手授权** 分配允许使用的助手。还需具备 AI 入口权限、相应工具权限，并有可用模型及助手配置，才能完成对应任务。

角色拥有业务菜单不代表自动拥有 AI 助手权限；助手授权也不会扩大业务数据范围。完整配置见 [AI 配置与运维](../operations/ai)，使用方法见[应用内 AI 助手](./ai)。

## 常见问题

**为什么部分角色没有编辑或授权按钮？** 除操作权限外，角色还必须在当前账号的可授权范围内。

**为什么选择“仅本人”后仍能看到更多记录？** 检查其他启用角色，以及对应业务模块是否应用数据范围规则。

**如何删除角色？** 当前 Web 删除入口要求超级管理员身份及对应删除权限，服务端还会校验引用和保护规则。先检查使用该角色的用户，再按实际提示处理。
