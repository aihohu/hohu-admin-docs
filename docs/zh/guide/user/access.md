# 成员与权限配置

本页帮助管理员完成首次授权。用户、角色、部门各有独立的管理权限，拥有列表查看权限不代表可以修改或授权。

## 配置顺序

| 顺序 | 操作                      | 目的                               |
| ---- | ------------------------- | ---------------------------------- |
| 1    | [建立部门](./departments) | 确定组织层级和人员归属             |
| 2    | [配置角色](./roles)       | 分配菜单、按钮和数据范围           |
| 3    | [创建或编辑用户](./users) | 设置部门及主部门，分配启用的角色   |
| 4    | 用普通账号验证            | 确认可见页面、可执行操作和可见记录 |

## 示例：为新同事开通访问

以下以“运营部新同事”为配置示例，部门与角色名称按你的组织实际情况填写。

1. 在部门管理中创建或确认“运营部”。
2. 在角色管理中创建业务角色，勾选工作所需的菜单与按钮。需要限制可见人员时，选择合适的数据范围。
3. 在用户管理中创建账号，选择角色及部门，并确认主部门、账号和角色状态。
4. 将站点地址、租户信息和初始登录信息交给本人。请本人修改密码并验证恢复邮箱。
5. 用该账号检查目标菜单、按钮及记录。需要 AI 助手时，继续配置 [AI 授权](./roles#ai-access)。

菜单权限决定能进入哪些功能，按钮权限决定能执行哪些操作，数据范围约束适用业务接口中的可见记录。仅有部门归属不会自动产生业务操作权限。

## 授权边界

管理员只能在自身授权范围内管理用户、部门及可分配角色。默认租户的系统超级管理员可以执行获准的系统管理操作，其他租户的管理员管理所属租户。

多个启用角色的数据范围取并集，详见[角色与权限](./roles#data-scope)。测试时应使用目标用户身份，不能用超级管理员的可见结果代替验证。

变更后出现缺失菜单、数据范围不符或权限拒绝时，按[权限排查](./faq#permissions)逐项检查。
