# AI 使用与开发

HoHu 提供两种 AI 使用方式：通过编程助手与 HoHu Skills 创建、开发应用；在已运行的应用内，通过 AI 助手查询和处理业务数据。两者的模型配置和权限分别管理。

## 选择你的任务 {#start}

| 你的任务               | 推荐路径                                                   | 准备条件                                    |
| ---------------------- | ---------------------------------------------------------- | ------------------------------------------- |
| 创建项目、开发业务模块 | [安装 Skills](../cli/skills) → [AI 辅助开发](../ai-coding) | 支持 Skills 的编程助手、HoHu CLI 和开发环境 |
| 在应用中查询或处理业务 | [应用内 AI 助手](../user/ai)                               | 可登录账号、可用助手与模型、对应业务权限    |
| 首次配置 AI            | [配置与运维](../operations/ai#first-setup) → 普通用户验证  | 默认租户系统超级管理员、模型服务凭据        |
| 接入自己的业务模块     | [业务工具接入](../development/ai-tools)                    | 已有 Service、功能权限和数据可见范围        |

## 用 AI 创建和开发应用 {#development}

HoHu Skills 为 Claude Code、Cursor、Codex、OpenCode、TRAE 等编程助手提供工作流：

| Skill                  | 负责什么                                                   |
| ---------------------- | ---------------------------------------------------------- |
| `hohu-project`         | 使用实际 CLI 创建、初始化、启动和排查项目                  |
| `hohu-business-module` | 按项目规范开发业务模块，接入权限、页面、应用 AI 工具并验证 |

在准备使用助手的工作区安装：

```bash
npx skills@latest add aihohu/hohu-skills
```

选择所需 Skill、编程助手和安装范围，确认助手已识别后提出需求。例如：

> 创建 equipment 项目，只需要 Backend 和 Web，初始化并启动。然后开发设备借用模块，支持借用、归还和查看记录，普通用户只能查看自己的借用记录，业务内容只需中文。

设备借用是开发需求示例，不是安装后自动获得的内置应用。Skills 指导助手实施和验证，交付结果应检查实际页面、权限、测试和 AI 工具执行记录。完整过程见 [AI 辅助开发](../ai-coding)。

安装要求、编程助手标识与更新方式见 [安装 Skills](../cli/skills)。安装 Skills 不会安装 HoHu CLI，也不会配置应用模型或授予业务权限。

## 在应用中使用 AI 助手 {#application}

打开 **AI 对话**，选择可用模型，使用自动路由或手动选择助手。先完成一次只读查询，再尝试需要确认的操作：**描述任务 → 核对目标与影响 → 确认执行 → 检查工具结果和业务页面**。

当前内置助手的发布范围如下。实例实际可用能力还受启用状态、角色绑定、功能权限和数据范围约束。

| 助手         | 当前能力                                                       | 边界                                           |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------- |
| 用户管理助手 | 用户查询、统计、创建和修改、部门与角色分配、导入导出及受控删除 | 写入及导出需按工具流程确认                     |
| 角色权限助手 | 角色查询、受限委派角色创建与修改、菜单和助手授权集合管理       | 授权受委派范围限制；删除走传统页面             |
| 部门管理助手 | 部门查询、创建、修改和组织树移动                               | 部门删除走传统页面                             |
| 通用工具助手 | 解析已上传文件，返回结构化摘要                                 | 需文件解析权限和有效工具策略，不负责跨业务管理 |

系统配置、AI Provider 和定时任务助手尚未发布，不作为当前可用能力。自定义业务需要开发并注册对应工具，新增 HTTP API 不会自动成为 AI 工具。

助手通过工具执行操作，仍受当前账号权限、租户边界和数据范围约束。模型回复不等于操作成功；以工具结果和业务页面为准。操作和排错见 [应用内 AI 助手](../user/ai)，管理配置见 [配置与运维](../operations/ai)。
