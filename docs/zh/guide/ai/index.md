# AI

HoHu 的 AI 能力覆盖源码开发和应用内业务操作。选择与你当前任务对应的入口：

| 你要做什么                   | 从哪里开始                                                 | 需要准备什么                                          |
| ---------------------------- | ---------------------------------------------------------- | ----------------------------------------------------- |
| 让编程助手创建项目或开发模块 | [安装 Skills](../cli/skills) → [AI 辅助开发](../ai-coding) | 支持 Skills 的 Agent、开发环境；项目创建还需 HoHu CLI |
| 在已部署应用中查询或处理业务 | [应用内 AI 助手](../user/ai)                               | 可登录的账号、可用模型与助手、对应业务权限            |
| 让应用内助手操作自己的模块   | [业务工具接入](../development/ai-tools)                    | 已有模块的 Service、功能权限和数据范围                |
| 配置模型、助手及运行环境     | [配置与运维](../operations/ai)                             | 对应管理权限、模型连接和部署配置                      |

## 用 Skills 开发项目

HoHu Skills 为 Claude Code、Cursor、Codex、OpenCode、TRAE 等编程助手提供项目工作流。`hohu-project` 通过实际 CLI 创建、初始化和启动项目；`hohu-business-module` 按目标项目规范实现数据库、接口、权限、页面和应用 AI 工具。

先按[安装指南](../cli/skills)安装，再在能发现 Skills 的工作区提出需求，例如：

> 创建一个 equipment 项目，只需要 Backend 和 Web，初始化并启动。然后开发设备借用模块，支持借用、归还和查看记录，业务内容只需中文。

业务模块默认接入应用内 AI。国际化遵从你的明确要求，未说明时沿用目标业务模块惯例；HoHu 自带国际化保持原有行为。完成后检查实际页面、权限、测试结果和 AI 工具执行记录，具体步骤见[AI 辅助开发](../ai-coding)。

## 在应用内使用 AI

应用内助手通过已注册的业务工具查询和处理数据。工具调用是助手请求执行具体业务能力，例如查询借用记录或归还设备；它仍受当前账号的功能权限、租户边界和数据范围约束。

首次使用从只读查询开始。需要确认的写入操作会展示确认卡片，核对对象和影响后再批准。模型回复不等于业务操作已成功，应以实际工具结果和页面数据为准。操作说明见[应用内 AI 助手](../user/ai)。

安装 Skills 不会配置应用模型或授予业务权限。开发完成但助手不可用时，按[配置与运维](../operations/ai)检查模型连接、助手启用状态及角色授权。
